# Developer commentary (added 2026-10-12)

Neatlogs raised this incident and ran a full investigation. The agent's 
diagnosis is partly right and partly wrong — recording it here honestly:

**Right:** A budget conflict CAN be claimed without cost data. When price 
lookup returns nothing for a model, the prompt gets no prices for it. 
Nothing in the code removes a budget conflict the model invents when no 
cost exists, so a hallucinated violation goes through. Most likely cause 
for gpt-4o: lookup returned empty.

**Not right:** Neatlogs claimed pricing was never injected into the Pivot 
Check prompt. It is — see pivot.py:184 ("Price facts (list prices; use them 
for budget conflicts): {prices}"). That section has existed since commit 
35c6162 (2026-10-11, before this incident was raised).

**Fix (roadmap):** When no cost was computed, drop any budget-node conflict 
the model returns and say "no price data." Few lines in pivot.py plus one 
test. Not shipping tonight.

**What this demonstrates:** Neatlogs' Investigations feature correctly 
found a real agent failure mode in NotByDefault. It wrote a wrong root 
cause for the "why", but the "what" is a legitimate bug we're tracking. 
That's exactly the signal / noise ratio you want from an incident tool: 
real finding, imperfect explanation, zero manual digging to get here.

## What we know so far
The agent incorrectly flagged a budget violation when evaluating a switch to `gpt-4o` because the prompt context lacked pricing data. Although the workflow executed a price lookup step, the retrieved pricing information was not injected into the LLM prompt. Consequently, the model relied on assumed external pricing metrics to claim that the $375 monthly budget would be exceeded. It remains unknown whether the price lookup tool returned empty results or if the prompt template simply omitted the retrieved data.

## Evidence
- The agent reported that switching models would exceed the monthly budget constraint without cost data present in the graph. (notbydefault.pivot_check)

## Recommended action
### Inject price lookup results into the LLM prompt context

**Steps**

1. Modify the `notbydefault.pivot_check` workflow to capture the output of the `price_lookup` step.
2. Update the LLM prompt template for the pivot check to include a dedicated section for model pricing data (e.g., `{{model_pricing}}`).
3. Pass the retrieved pricing data from `price_lookup` into the prompt context so the LLM can perform grounded cost calculations.
4. Instruct the LLM in the system prompt to only flag budget conflicts if supported by the provided pricing data, and to explicitly state if pricing data is missing instead of assuming external rates.

**Verification**

- Run a test case with the updated workflow where `price_lookup` returns known pricing for `gpt-4o`.
- Verify that the LLM input contains the pricing data and that the LLM output correctly references these figures in its budget evaluation.
- Run a test case where pricing data is unavailable and verify that the LLM does not hallucinate a budget violation.
